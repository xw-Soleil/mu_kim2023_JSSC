# 整芯片 ICC2 首链记录(pde_chip_pads,R3 前置)

2026-08-15。顶层 `pde_chip_pads`(SPI 接口 + 9 信号 pad),输入为 `dc28_pads_20260814` 的网表与 SDC(6ns)。运行目录 `flow/local_runs/icc2_28nm_chip_20260815c/`(a/b 两次为失败前身,保留供追溯);语法与语义试探全程留档于 `flow/local_runs/icc2_28nm_synprobe_20260814/`(probe1-25)。体例先证据后判定。

## 1. 结果

s01→s07 全链过闸,六硬门全零:setup 违例 0(关键路径 3.54ns,6ns 下裕量 +1.16ns,TNS 0)、hold 违例 0、几何 DRC 0、antenna 0、open 0、short 0(豁免类见 §3)。die 精确 685×685µm(DEF DIEAREA 实测),core 415×415,利用率 0.7806,叶单元 146,385。产物六件套齐:GDS(156MB,含 bond pad 全栈)、DEF、postroute.v、WC/BC SPEF、SDF。

GDS 复核(python 逐记录解析):21 只 PAD50GU 引用坐标与 RING_TABLE 槽位经旋转变换逐一吻合(dbu 0.1nm);PAD50GU 单元含层 35/36:20/37:20/38:80/39:80/74(AP)/76(CB)/86:20/108/157 全栈;9 个 PAD_* 端口 text 落在 M7(层 37),位于 bond pad 落点条正下方。

## 2. 实现要点(相对 core-only 流程的全部增量)

- 库侧(pdk28_bringup/,仓库外):GPIO 库 NDM `tphn28hpcpgv18.ndm`(123 单元,WC=ssg0p81v1p62vm40c/BC=ffg0p99v1p98vm40c 过程标签,`build_ndm_io.tcl`)、bond pad NDM `tpbn28v.ndm`(自写最小 LEF `lef/tpbn28v_pad50gu.lef` + 真 GDS 合并,`build_ndm_bondpad.tcl`);编库时对 lib cell 补 design_type 标注(pad/corner/pad_spacer/cover),LEF 的 CLASS 信息不进 design_type,缺标注会使 create_io_guide -pad_cells 拒收(DES-122)且 filler 铺到 pad 上。
- 流程侧(入库):`s02_floorplan_chip.tcl` 新阶段脚本(die 驱动 `-boundary` 精确 685、显式坐标摆 21 pad + 4 corner 并内置 bbox 断言、逐缝隙 IO guide + filler、环连续性审计含缝隙与重叠双检、PG 环/轨照抄 core 版、四只核电源 pad 的 1.6µm 细指 strap、9 端口 M7 terminal);`pnr28_common.tcl` 加 IS_CHIP/IO_NDM/BOND_NDM、泛化 PG 连接助手(+VDDPST/VSSPST/POC)、chip_lvs_counts 豁免过滤器;`s01_setup.tcl` 条件 ref_libs + pad dont_touch;`s06b/s07` 门槛接入过滤器;`s07` 硬门后插入 bond pad。s03-s06 零修改。

## 3. 豁免类(全部为工具连通性模型盲区,非版图问题;最终仲裁 = Calibre)

1. check_lvs "open"(VDD/VSS/VSSPST):核电源经 strap 指条→bond pad 厚板→厚板内建 VIA7/VIA8 阵列→pad 的 M5-M7 strip 引脚,后两跳在无引脚 COVER 单元内部,checker 不可见;IO 环总线靠单元邻接连续,同为盲区。仅豁免五条 PG 网名,其余 open 照旧硬门。
2. check_lvs "short"(160 条):环单元贴边线接触,bbox 全部 ≤2nm 宽(零面积);根因是 IO .db 无电源 pad 的逻辑视图,connect_pg_net 无法将其总线引脚绑网,邻接线被记跨网。仅豁免"环单元参与且 bbox 细于 0.01µm"的组合,面积重叠类 short 照旧硬门。
3. check_pg_connectivity 报 121 个环单元 floating:同一盲区(报告性检查,本就不入硬门);四只核电源 pad 的 strap 环侧 via 以脚本断言强制(南 32/32、东 67/67)。

## 4. 关键教训(过程实录,详见 synprobe 目录)

- 该版 ICC2 的 PG via 只在 create_pg_strap 对已登记对象的自动创建路径上落 PAD 类单元相关 via;独立 create_pg_vias 对 pad 引脚一律 0 提交,粗 strap(8µm)因 tf 缺 fatWire via 表全部"not fixed"回收——细指条(1.6µm)+ 自动 via 是唯一通路。
- 电源 pad 的 VDD/VSS 引脚 M5-M7 条在 bond 落点位置(y 70.05-73.05),不在内沿(内沿 y≈103-108 只有 M2/M3 口 + 全单元 M6/M7 OBS);首版 strap 打在 OBS 上全军覆没。
- `initialize_floorplan -side_length` 吸附 site 网格(685→684.96/684.90),`-boundary` 多边形精确保边;`set_cell_location -coordinates` 是旋转后 bbox 左下角,cell `origin` 属性才是变换原点,bond pad 叠放须直写 origin/orientation 属性。
- create_io_filler_cells 无 pad 关联时铺满整条 guide(首链 s06 的 32 个不可修 short 即 filler 叠 pad 所致);逐缝隙短 guide 从构造上排除。
- s02 之后新插的单元(CTS/hold 修复)PG 引脚未绑网,check_lvs 会把引脚压轨记 short;s06b 判门前先 connect_named_pg_pins。
