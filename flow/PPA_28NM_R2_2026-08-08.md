## 第一部分 Stage K 前置修复(均经用户确认)

### K.1 gdsout 端口 text 层归位(根治,替代第一轮 J.1 runset 补丁)

机制:`write_gds` 的 layer map 原生支持对象类型限定行(man 规则 a–f)。
补丁 map 副本 `pdk28_bringup/patch/gdsout_4X2Y2R_porttext.map`
(PRTF 原件不动,sha256 41307a93…)追加三行:

```
text 33:0:* 133:0
text 34:0:* 134:0
text 39:0:* 139:0
```

隔离冒烟(测试库三端口)与 R2 实 GDS 双重验证:顶层 TEXT 全部落
133/134/139;0(实测 133;0 ×28、134;0 ×29、139;0 ×2),几何(含 M9 的
39;80)与原 map 逐位一致——只动 text。Stage N 的 LVS runset 因此删除
J.1 的 9 条补丁语句(K.1 批准时同步裁决),J.2 FILTER 保留。

### K.2 高扇出目标(前提修正,证据在案)

原指令假定在 DC 阶段压 fanout;实测:DC 输出网表 `HFSBUF|HFSNET` 计数
= 0,postroute = 1,832 ——**高扇出缓冲全部由 ICC2 插入,DC 侧无事可改**。
根因精确定位:ICC2 W-2024.09 `opt.common.max_fanout` 系统默认值 = 40
(report_app_options 实测),与 PT 报的 fanout-40 严丝合缝。修复:s01
`set_app_options -name opt.common.max_fanout -value 32`,SDC 不动。
用户确认接受该前提修正(2026-08-08)。

### K.3 Calibre 版本对齐

Calibre 2023.2(EDAServer,65nm 线勘误 33a3aa6 实证)冒烟:SVRFencrypt
v2016.4 加密 DRC deck 解密执行成功(QA 样片,RC=0)。本轮三项签核全部
