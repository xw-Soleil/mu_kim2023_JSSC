| 单元 | 存在 | SIZE | LEF CLASS |
|---|---|---|---|
| **TAPCELLBWP40P140** | ✓ | 0.560 × 0.900 µm,SITE core | `CORE ;` |
| **BOUNDARY_LEFTBWP40P140** | ✓ | 0.420 × 0.900 µm | `CORE ;` |
| **BOUNDARY_RIGHTBWP40P140** | ✓ | 0.420 × 0.900 µm | `CORE ;` |

- CLASS 分布:**1,044/1,044 全部 `CLASS CORE ;`**——没有 `CORE WELLTAP`/`ENDCAP` 子类标记。

  ICC2 的 tap/boundary 插入必须**按单元名显式指定**,不能用 CLASS 查询筛选。
- databook(DB_TCBN28HPCPLUSBWP40P140_TT0P9V25C.pdf,已抽验)有正式的 **TAP 节**与 **BOUNDARY 节**
  (单元信息、宽度、PG pin),但**不含插入间距规则**——间距规则在 DRM 的 LUP 章节
  与库应用笔记中,两者均不在本次下载(见任务 5 与决策项 1)。

## DRM 三判据终审(2026-08-07,按用户提出的闭合标准逐项落实)

1. **15 个 tn28cldr\* 全开箱** ✅ —— 全部是工具交付(DRC/dummy/LUP/RTO deck)
   + 35–45 KB 的 revision 说明页,无 DR-001 手册。
2. **tsmc28hpc+.zip 逐层穿透** ✅ —— zip → 外层 tar(6 成员)→
   `DOC_iPDK...tar.gz`(**79 个 PDF 逐一枚举**:PDK 用法/LVS deck 用法/模型/
   dummy utility/guard-ring utility 等,无一是 DRM)。内层 iPDK 数据 tar 不必
   再穿透:readme 自述 "PDK_doc/ : Includes all documents"。且 readme 的措辞
   本身就是佐证——"cells ... built based on current design rule documents"、
   "please based on DRM/DFM rules",即 **DRM 是被引用的外部独立交付物**。
   全树 chm/html/doc 扫描:0 命中。
3. **PDK(hpc+).xlsx 全量 dump** ✅ —— 共 13 个字符串,是 iPDK 单行目录卡
   (仅列 T-N28-CL-SP-079-W1),无 TN28CLDR001。

**终审结论:整套资料确定不含可阅读的 DRM(TN28CLDR001 / T-N28-CL-DR-001)。**
这与 TSMC 交付模式一致:DRM 经文档平台单独下发,不随 PDK/deck 打包。

措辞修正(采纳用户意见):
- ✅ 数字后端流程(DC / ICC2 / Calibre 签核 / chip 级):**资料无阻塞**;
- ⚠ 但不称"资料零缺口"——**缺 DRM 是真实文档缺口**,影响场景:DRC 报错查
  规则原文、自制/修改标准单元版图、guard ring 等定制物理设计与规则理解。
- 补齐途径:向渠道单独索取 **TN28CLDR001**(1.7/1.8 版皆可,RC 文件名标注
  DRM1.8_R,优先 1.8)。

DOC 包顺带入账的有用文档:`N28_Calibre_LVS_Deck_Usage.pdf`、
